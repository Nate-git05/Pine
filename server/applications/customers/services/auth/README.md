# Customer authentication service

`auth_service.py` supplies the six-digit code generator and Twilio SMS sender, `AuthState`, REST's `get_current_customer` dependency, and GraphQL's `get_customer_context`. Both use the shared `HTTPBearer` dependency to extract a Bearer token, parse its UUID, HMAC-hash it with the Pine server secret, look up the Postgres session, check expiry, update `validated_at`, and load the customer. `HTTPBearer` does not tie token extraction to a particular token-issuing route.

Signup/login temporary tokens and flow data live in Redis; the final session token is not stored in plaintext. The GraphQL context uses `CustomerContextRequest.model_validate_json` to validate request-body cursor fields and falls back to query parameters for GET requests. It passes `cursor` and `last_id_seen` through to resolvers, returning `None` when absent. The auth schema is described in [`schemas/auth/README.md`](../../schemas/auth/README.md). See the [auth route guide](../../routes/auth/README.md) for the login lifecycle. No logout/revocation endpoint is registered.
